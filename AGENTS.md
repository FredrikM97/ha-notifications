# HA Notifications

## Orientation

This repository is a Home Assistant custom integration with a Lit/TypeScript
frontend. Alert configuration is canonical; generated Home Assistant
automations are derived from it. The backend does not currently persist
notification history.

## Repository Map

- `custom_components/ha_notifications/`: authored Python integration,
  configuration validation, automation generation/reconciliation, services,
  and websocket bridge.
- `frontend/`: authored Lit frontend; `frontend/panel.ts` is the bundle entry
  point and `frontend/api.ts` is the Home Assistant transport boundary.
- `tests/backend/`: pytest tests, canonical JSON/YAML fixtures, and Syrupy
  snapshots for the integration.
- `tests/frontend/`: Vitest tests, browser fixtures, and frontend snapshots.
- `tests/contracts/`: backend/frontend command and runtime contract fixtures.
- `docs/development.md`: setup, validation, local installation, and packaging.

## Boundaries

Keep persistent alert configuration separate from Home Assistant runtime state.
Preserve native Home Assistant trigger, condition, template, and action data
when validating or serializing configuration. Do not reintroduce the removed
`controller/`, `delivery/`, `features/`, or `support/` implementation paths.

`build/` is generated by `npm run build` and is ignored; edit the authored
integration and frontend sources instead. The generated frontend stays in
`build/` until the local install or HACS packaging step stages it with the
integration.

Keep `README.md` short and stable: overview, installation, basic usage, the
dashboard card snippet, and documentation links. Put configuration examples
and feature-specific details in `docs/`, not in the README; avoid per-feature
README churn.

## Validation

Finish implementation changes first, then add or update tests and run them.
Do not interleave test authoring or test runs with unfinished implementation.

Batch validation around coherent changes instead of rerunning checks after
every small edit. Finish related edits first, then run the narrowest relevant
checks once for that slice; run the repository gate before handoff. Avoid
repeating unchanged checks after minor follow-up edits unless they affect the
validated behavior.

Typical checks are:

```bash
python3 -m pytest tests/backend/test_automation.py
npm run typecheck
npm run build
```

For backend changes, exercise the behavior with the real Home Assistant core
fixtures in `tests/backend/conftest.py` before falling back to pure unit tests
or local stubs. For frontend changes, check behavior in a real Home Assistant
with `npm run dev`.

Prefer snapshot testing for serialized contracts, generated automations,
payloads, and complete structures whenever practical. Use manual assertions
for focused behavior, invariants, validation status, and error handling that
snapshots cannot express clearly.

Run the repository gate before handoff:

```bash
sh scripts/validate.sh
```

See the scoped `AGENTS.md` files in `custom_components/ha_notifications/`,
`frontend/`, and `tests/` for subsystem-specific navigation and checks.
